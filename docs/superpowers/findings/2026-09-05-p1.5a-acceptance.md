## 验收项 8：审计检索的过滤与翻页（含一处真实缺陷的发现与修复）

### 发现的缺陷：`to` 参数按裸日期解析成当天零点，导致当天数据被排他上界整个排除

第一次在浏览器里打开「安全合规 → 审计检索」页（默认时间范围「最近 7 天」，`to` 参数是今天的裸日期 `2026-09-06`），页面只显示了 2 条 2026-09-01 的历史遗留记录，**当天新造的 6 条 p15a 记录全部不见**。

排查：`Records` 查询用的是 `ts >= from AND ts < to` 排他上界；`parseOneTime` 把裸日期 `to=2026-09-06` 解析成 `2026-09-06T00:00:00Z`（当天零点）。于是 `ts < to` 变成「严格早于今天零点」——**今天一整天的记录，不论多少条，全部被排除在外**。这不是边界条件的小瑕疵，是「选择包含今天的范围」这个最常见操作直接失效。

修复：把 `parseOneTime` 拆成 `parseRangeStart`（裸日期 = 当天零点，不变）与 `parseRangeEnd`（裸日期 = **次日**零点），让排他上界真正覆盖到选定的那一天结束。按 TDD 补了失败测试 `TestParseRangeToDateIsInclusiveOfWholeDay`（先红后绿），同时更新了一条断言依赖旧语义的既有测试（`TestParseRangeAcceptsExplicitDates`：`to.Day()` 从 8 改为 9，因为 `to=2026-09-08` 现在正确解析成 9 月 9 日零点）。`go test ./internal/control/...` 全绿后单独提交（`fix: 裸日期的结束时间解析成次日零点，覆盖当天全部数据`）。

修复后复测：

```
$ curl ".../api/audit/records?from=2026-08-30&to=2026-09-06&limit=50" -H "Cookie: airlock_session=<sec token>"
8 条，org_id 覆盖 ['p15a-rd', 'p15a-rd2', 'rd']
```

界面复测（浏览器，安全合规官会话）：

```

"2026/9/6 08:08:47 P15a-RD2（同前缀兄弟节点） u-p15a-plain 429 ..."
"2026/9/6 08:08:32 P15a-RD u-p15a-plain 401 ..."

```

**当天记录与历史记录同时正确显示，组织名与成员名都正确还原成人话。深链落点（P1.4a 修复）与账号名解析（P1.4c 的 `userLabel`）在这条链路上也一并复测通过。**

## 过程中发现的问题及处置

1. **`to` 参数的裸日期解析成当天零点，导致排他上界排除当天全部数据**——已在验收项 8 完整记录：真实缺陷，按 TDD 修复（`parseRangeEnd` 把裸日期解析成次日零点），修复已提交并覆盖新增与更新过的单元测试。

2. **验收过程中违反了一次操作纪律，导致夹具被清空**——修完上面那处缺陷后，为验证修复我跑了 `POSTGRES_DSN=... go test ./internal/control/...`，而此时手工 E2E 验收仍在进行中、且用的是同一个共享开发 Postgres。测试套件的 `cleanTables` 清空了 `users`/`sessions`/`organizations`/`role_grants` 等表，把这次验收的全部 Postgres 侧夹具（含浏览器登录创建的管理员账号）连同前几期可能残留的数据一并清空。这正是 P1.3b 验收记下的「手工 E2E 与 `make test` 不能共用同一个数据库」纪律，这次又实打实地违反了一次。

   **恢复过程**：ClickHouse 是独立存储，不受 Postgres 的 `cleanTables` 影响，直接查库确认 `p15a-rd`/`p15a-rd2` 的 6 条用量记录完好无损；用同一份夹具 SQL（相同的组织 ID、用户 ID）重新灌入 Postgres，让新夹具与已经写入 ClickHouse 的历史用量记录重新对上号，随后完整重做了验收项 1–9 的全部 curl 与浏览器步骤，逐条记录在本文档中。**除了本条以外，所有验收证据均来自清库后重做的第二轮，是自洽的一整套。**

   **教训**：发现并修复代码问题后，验证修复的冲动会让人忘记「验收仍在进行中」这个前提。以后再遇到类似情况，应该先把当前手工验收的进度全部记录、明确「阶段性结束」之后，再去跑任何触碰共享数据库的自动化测试；或者用一个不会被测试套件清空的临时数据库连接单独验证修复。

3. **`group_by=model` 对失败的调用返回空字符串**——Edge 在鉴权失败（401/429）时不记录具体请求的模型名，这是 Edge 既有的行为，与本期新增的报表接口无关。按维度聚合时空字符串会被当作一个合法的维度值分组显示，这是**正确**的行为（不隐藏任何真实数据），如实记录，不作为缺陷处理。
