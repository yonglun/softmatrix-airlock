## 手工核对成本正确性（PRD 验收标准 A2）

定价表：`InputPer1M=2000000`，`OutputPer1M=8000000`（Micro，1e-6 元/1M tokens）。

**非流式调用（Step 6 响应体）**：`prompt_tokens=12`，`completion_tokens=36`。

```
预期成本(Micro) = 12 * 2000000 / 1000000 + 36 * 8000000 / 1000000
              = 12 * 2 + 36 * 8
              = 24 + 288
              = 312
```

ClickHouse 实际 `cost_micro = 312`。**完全一致。**

**流式调用（ClickHouse 记录里 Edge 自行捕获的 usage，未下发给客户端）**：`input_tokens=9`，`output_tokens=28`。

```
预期成本(Micro) = 9 * 2000000 / 1000000 + 28 * 8000000 / 1000000
              = 9 * 2 + 28 * 8
              = 18 + 224
              = 242
```

ClickHouse 实际 `cost_micro = 242`。**完全一致。**

两条记录的成本计算与手工核算逐分对齐，符合 PRD 验收标准 A2。

## 遗留问题

### 发现的缺陷（已在本次验收中修复并提交）

- **`IsUsageOnlyChunk` 未覆盖真实上游的块形状**：验收 Step 7 首次运行时，`grep -c '"usage"' stream.txt` 返回 `1`（预期 `0`），说明 Edge 自行注入 `include_usage` 后产生的 usage 块没有被剥离、泄漏给了客户端。定位到 `internal/openai/usage.go` 的 `IsUsageOnlyChunk` 原实现要求 `choices` 必须是空数组才判定为"纯 usage 块"；但真实的 `gpt-5.6-luna`（Azure AI Foundry 部署）在流末尾发送的 usage 块里 `choices` 是 `[{"index":0,"delta":{}}]`（一个 delta 为空对象、且没有 `finish_reason` 的占位 choice），不是空数组。此前的单元测试（`internal/edge/stream_test.go`、`internal/openai/usage_test.go`）里 mock 的 usage-only 块统一写的是 `"choices":[]`，因此单测全绿但没能覆盖这个真实上游的形状——这正是本次端到端验收要抓的问题类型。已修复 `IsUsageOnlyChunk`，改为：choices 为空，或者其中每个 choice 的 `delta` 都是空对象且都没有 `finish_reason` 时，均判定为 usage-only；并补充了对应的回归测试（含"占位 choice"、"带 finish_reason 不算 usage-only"、"usage 显式为 null 不算 usage-only" 三个新用例）。修复后 `make test -race` 全绿，重新跑 Step 6/7 验证问题已解决。提交哈希：`43eb84f`。
- 这也提示：目前单元测试对上游 SSE 块形状的 mock 覆盖面偏窄，只覆盖了"OpenAI 标准形状"（`choices:[]`）。建议 P1.2 阶段在对接更多真实上游/模型时，为常见非标准形状（如本次发现的"占位 choice"）建立一个共享的 fixture 集，而不是每个测试各自手写字面量。

### 已知的、计划内的延后事项（非缺陷）

- **密钥与定价的真实数据库读取延后到 P1.2/P1.3**：`internal/app/edge.go` 当前用 `apikey.NewMemoryStore` 与 `pricing.NewMemoryTable`，本次验收为了跑通全链路，用了一个不提交的临时装配程序从 Postgres 读一次数据灌进内存态实现。P1.2/P1.3 需要把这一步做成常驻的、支持定期刷新/热更新的数据库读取路径，而不是像本次这样一次性读取后进程内不再变化。
- **模型覆盖面有限**：本环境中只有 `gpt-5.6-luna`（Azure AI Foundry）配置了真实可用的凭证；`deepseek-chat`、`qwen-plus`、`gpt-4o-mini` 在 `deploy/litellm/config.yaml` 里虽有配置但缺少可用的 API Key，本次验收未能覆盖。多提供商/多模型的价格档位与响应格式差异（例如本次发现的 `choices` 占位块问题）仍需要在拿到更多真实凭证后逐个验证。
- **临时装配程序模式**：为了在不改动 `internal/app/edge.go` 正式装配代码的前提下验证数据库读取链路，本次用了两个放在模块内、验收结束后删除的临时目录（`tmp_e2e_seed/`、`tmp_e2e_server/`）。这是一次性验收手段，不是长期方案；P1.2 实现真实的数据库背书装配后，这类端到端验收应该改为对正式 `airlock edge` 二进制直接测试，不再需要临时装配程序。
- **P1.2a 已将 `cmd/edge` 重构为 `cmd/airlock` 子命令**：本文档中的 `cmd/edge/main.go` 路径引用已更新为 `internal/app/edge.go`，`make migrate` 底层命令已从 `go run ./cmd/edge -migrate-only` 改为 `go run ./cmd/airlock migrate`。验收时的行为与结论不受影响。
